# Mixdog Fork AI Rules

Android/mobile-focused fork of `tribgames/mixdog`; the full upstream tree is retained for mergeability.

## Core Rules

- Fork product edits stay in `apps/mobile/**` with Korean intent markers; unavoidable outside edits follow [FORK_RULES](docs/ai-rules/FORK_RULES.md).
- Every fork change has a [ledger entry](docs/ai-rules/FORK_CHANGES.md); fork-owned rule/audit files need no code markers.
- Upstream updates use the merge-only [SYNC_UPSTREAM](docs/ai-rules/tasks/SYNC_UPSTREAM.md) procedure; preserve uncommitted work first.
- Conflicts follow [FORK_RULES](docs/ai-rules/FORK_RULES.md) priorities; case c waits for user approval, identity stays fork, security fixes land.
- APK versioning, signing and publication follow [RELEASE_APK](docs/ai-rules/tasks/RELEASE_APK.md); push only to the fork with explicit task authorization.
- Preserve shared native/web authorization and pairing order under [CODING_RULES](docs/ai-rules/CODING_RULES.md).

## Run commands

```bash
cd apps/mobile
npm ci
npm run check
npm run test:java
# APK build/sign/publish: load tasks/RELEASE_APK.md first.
# Upstream merge: load tasks/SYNC_UPSTREAM.md first; no DB migration task is defined.
```

## File Layout

Mobile tests live beside modules in `apps/mobile/src/`; shared vectors live in `apps/mobile/test-vectors/`.
Mobile tooling lives in `apps/mobile/scripts/`; upstream trees remain upstream-owned.
Uppercase Markdown files under `docs/ai-rules/**` are AI/team rules; lowercase Markdown files are analysis/reference.
`.rule-architect/` is generation audit state, not runtime routing material.
