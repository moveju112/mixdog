# Build and Publish a Fork APK

Use task-scoped approval or the phone-app-update standing authorization in [AI_RULES.md](../../../AI_RULES.md). Standard app-update requests include versioning, checks, existing-key signing, task-only staging/commit, `origin/main` push and published APK release without repeated approval; an explicit narrower scope overrides this default. Fork ownership is in [FORK_RULES.md](../FORK_RULES.md); build numbers and versionCodes are recorded in [FORK_CHANGES.md](../FORK_CHANGES.md).

1. Select the authorized source revision on `main`; inspect pending work and preserve it. From `apps/mobile`, run `npm ci`, `npm run check`, then `npm run test:java`.
   `evidence: apps/mobile/package.json:13`, `evidence: .github/workflows/mobile-android.yml:143`.
2. Resolve the latest merged upstream mobile tag. The base command is `git describe --tags --match "mobile-v*" --abbrev=0`; after fork tags exist use `git describe --tags --match "mobile-v*" --exclude "mobile-v*.*.*.*" --abbrev=0` to ignore four-part fork tags. Confirm the resulting three-part tag belongs to upstream and is merged into `main`; initial base is `mobile-v0.1.13`. Set versionName `<upstream mobile version>.<NNN>`: `NNN` is a zero-padded three-digit fork build number per upstream mobile version; it starts at `001`, increments per fork build and resets to `001` when the upstream mobile version changes. Past `999`, widen to four digits (`1000`); the updater compares parts numerically. The first build `0.1.13.1` predates padding, so the next is `0.1.13.002`. Set versionCode to the previous fork build's versionCode + 1 from the ledger, independent of versionName (`101301` → `101302`). Never derive versionCode from the upstream version: such formulas reach Android's ceiling (`2100000000`), after which no update can be installed. Reserve the build in ledger history; never reuse a versionCode or `NNN`.
   `evidence: apps/mobile/android/app/build.gradle:12`, `evidence: apps/mobile/android/app/src/main/java/io/mixdog/app/MixdogAppUpdater.java:665`.
3. Confirm the backed-up signing key is configured as `ANDROID_KEYSTORE_PATH=/home/ubuntu/.android/mixdog-fork-release.jks`. The env file used by `source /home/ubuntu/.config/mixdog-fork/signing.env` has mode `600` and exports `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Never commit or print the keystore/passwords; avoid shell tracing. Losing this keystore makes in-app updates to existing fork installations impossible forever because the updater requires the same certificate. Back it up securely before release. Original `tribgames`-signed app users must uninstall once before installing the fork APK (preserve any needed app data first).
   `evidence: apps/mobile/android/app/build.gradle:24`, `evidence: apps/mobile/android/app/src/main/java/io/mixdog/app/MixdogAppUpdater.java:669`.
4. Set `JAVA_HOME=/home/ubuntu/.local/share/jdk/jdk-21` and `ANDROID_HOME=/home/ubuntu/Android/Sdk`; export both and include `$JAVA_HOME/bin` on `PATH`. JDK **21** is required, not merely a system Java default. Run `source /home/ubuntu/.config/mixdog-fork/signing.env` without displaying its content.
   `evidence: apps/mobile/android/app/capacitor.build.gradle:5`, `evidence: .github/workflows/mobile-android.yml:130`.
5. From `apps/mobile`, run `npm run sync:android`. The fork has no `google-services.json`, so FCM push does not work; Firebase provisioning remains out of scope until requested.
   `evidence: apps/mobile/package.json:15`, `evidence: apps/mobile/android/app/build.gradle:65`.
6. Enter `apps/mobile/android` and run `./gradlew --no-daemon assembleRelease -PmobileVersionName=<version> -PmobileVersionCode=<code>`, replacing both inputs with step 2's values (example: `-PmobileVersionName=0.1.13.002 -PmobileVersionCode=101302`). Do not rely on Gradle defaults or the upstream workflow's version formula.
   `evidence: apps/mobile/android/app/build.gradle:12`, `evidence: .github/workflows/mobile-android.yml:173`.
7. Verify `app/build/outputs/apk/release/app-release.apk` using the installed Android build-tools `apksigner verify --verbose --print-certs`; compare the certificate to the backed-up fork key/previous verified fork release without exposing passwords. Check APK versionName and versionCode against step 2, then copy it to `Mixdog-<version>.apk`. The updater accepts four-part versions numerically.
   `evidence: .github/workflows/mobile-android.yml:179`, `evidence: apps/mobile/android/app/src/main/java/io/mixdog/app/MixdogAppUpdater.java:437`, `evidence: apps/mobile/android/app/src/main/java/io/mixdog/app/MixdogAppUpdater.java:462`.
8. Record the build outcome and source revision in ledger history; keep APKs and secrets out of Git. Within task-scoped or standing authorization, stage only task changes, commit required source/ledger changes, push **main first** using only `git push origin main`, and capture the exact pushed main SHA. Do not publish an APK whose source code was not included in that pushed revision. Never push upstream tags, `--tags`, force or to `upstream`.
   `evidence: apps/mobile/android/app/src/main/java/io/mixdog/app/MixdogAppUpdater.java:65`.
9. Publish the verified asset with `gh release create mobile-v<version> <apk> -R moveju112/mixdog --target <pushed main sha> --title "Mixdog mobile <version> (fork)"`, replacing the inputs. Create a **published, non-draft, non-prerelease** release; the updater skips drafts/prereleases and accepts only fork-hosted APK assets. Confirm the tag target, attached APK and public release flags after publication.
   `evidence: apps/mobile/android/app/src/main/java/io/mixdog/app/MixdogAppUpdater.java:432`, `evidence: apps/mobile/android/app/src/main/java/io/mixdog/app/MixdogAppUpdater.java:444`.
10. The retained `.github/workflows/mobile-android.yml` fires on `mobile-v*` tags in the fork. Missing Firebase/signing secrets cause an expected failure; four-part tags also fail its three-part version validation earlier. Ignore this upstream job's expected failure, not local check/signature failures; do not change the workflow or add secrets without separate authorization.
    `evidence: .github/workflows/mobile-android.yml:15`, `evidence: .github/workflows/mobile-android.yml:112`, `evidence: .github/workflows/mobile-android.yml:156`.
11. Verify the public APK download against the verified local artifact's size and SHA-256, then provide the direct download link and target version. Ask the user to confirm the installed version on their phone. Do not claim device installation or complete the phone-update goal merely because the source was pushed or the release was published; device installation/control requires separate authorization.
